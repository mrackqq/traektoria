# ТРАЕКТОРИЯ — план переработки интерфейса

Документ описывает разбор текущего интерфейса, целевую систему и порядок
переписывания. Кода компонентов здесь нет — только решения и обоснования.

---

## 0. Что мы вообще проектируем

Прежде чем ругать оформление, нужно назвать предмет. Продукт отвечает
абитуриенту на три вопроса: **куда мне реально можно**, **что мне для этого
сделать** и **чего мы про это не знаем**.

Третий вопрос — то, чем этот продукт отличается от любого агрегатора вузов.
Ядро намеренно отказывается врать: оно различает «не выполнено» и
«неизвестно», показывает расхождение двух источников вместо удобного
среднего, отказывается подставлять час к сроку, если источник его не
указал, и вычёркивает из текста модели любую цифру, которой не было во
входных данных.

**Это и есть душа, которой, по ощущению, нет в интерфейсе.** Она есть в
данных, но оформление её прячет: неопределённость выглядит как ещё одна
серая плашка среди одинаковых белых карточек. Весь план ниже подчинён одной
идее — **сделать неопределённость полноправным гражданином интерфейса**, а
не сноской.

## 1. Разбор без скидок

### 1.1 Главная улика: таблица стилей написана дважды

`src/app/globals.css` — 668 строк, и это **два стилевых слоя, наложенных друг
на друга**. Первый слой идёт до строки 429. На строке 431 стоит комментарий
`/* User-first hierarchy: one next action, readable copy, optional detail. */`,
и дальше начинается второй слой, который **переопределяет первый**.

Измеримо:

| Показатель | Значение | Что это значит |
| --- | --- | --- |
| Селекторов объявлено дважды | **35** | `.btn`, `.card__eyebrow`, `.nav__link`, `.journey`, `.notice`, `.task__title`, `.main`, `h1`, `h2`… |
| Использований токенов отступа `var(--s-N)` | **4** | Шкала отступов объявлена и не используется |
| Литералов `px` в `padding`/`margin`/`gap` | **287** | Реальные отступы — магические числа |
| Уникальных `font-size` | **22** (9px…32px) | Практически каждое целое значение подряд |
| Уникальных hex-цветов | **142** | При ~20 объявленных токенах палитры |
| `!important` | **14** | Плата за борьбу двух слоёв между собой |
| Медиазапросов | **16** | На 8 различных брейкпоинтов |

Это ровно тот след, который оставляет итеративная правка вслепую: «сделай
крупнее и читабельнее» → новые правила дописаны в конец вместо изменения
исходных. Последствие не косметическое: **изменение токена больше ничего не
меняет**, потому что его перебивает литерал ниже по файлу. Дизайн-система
существует на бумаге.

**Прямое противоречие, найденное автоматически:**

```
строка 328:  @media (max-width: 960px) { .journey small { display: none; } }
строка 591:  @media (max-width: 960px) { .journey small { display: block; } }
```

Один и тот же брейкпоинт, противоположные правила, исход решается только
порядком строк в файле. Автор второго слоя не знал про первый.

### 1.2 Типографика: шкалы нет

22 размера шрифта без модульной шкалы. Хуже — **первый слой набран слишком
мелко** (`10px`, `11px` для подписей, `12px` для основного текста карточек),
а второй слой это чинит точечными переопределениями до `12–14px`. То есть
проблема была замечена и залечена симптоматически.

Осталось непочиненным: `.wordmark__sub` 10px, `.card__eyebrow` 10px в
`.start-preview`, `.demo-pill` 9px на мобильном, `.footer` 10px.

Межстрочный интервал задан как `1.65` глобально и переопределён локально на
`1.4`, `1.5`, `1.55`, `1.65`, `1.7`, `1.75`, `1.8` — семь значений без правила.

### 1.3 «AI slop» на первом экране

`StartScreen` (`src/app/_components/start-screen.tsx`) собран из канонического
набора признаков сгенерированного лендинга:

- градиентная панель `linear-gradient(125deg, #eaf4ec, #f4f8ee)` под всё;
- eyebrow с иконкой-искоркой и текстом «Ваш первый шаг»;
- справа карточка со списком преимуществ, пронумерованным **01 / 02 / 03**,
  каждый пункт — иконка в скруглённом квадрате плюс заголовок плюс строка
  пояснения;
- подпись со щитом «Без загрузки документов»;
- ещё одна подпись с галочкой внизу карточки.

Ни один из элементов не сообщает того, чего нет у конкурентов. Человек,
открывший сайт, узнаёт, что «на выходе — не просто список вузов», но не
видит **ни одного настоящего фрагмента продукта**. Между тем у продукта есть
что показать вместо обещаний: реальная карточка программы с честной пометкой
«источники расходятся» убедительнее трёх иконок.

Дополнительно: `aria-label` повешен на обычный `<div class="start-preview">`
(строка 54). На неинтерактивном `div` без роли он не озвучивается — подпись
не существует для скринридера.

### 1.4 Две конкурирующие системы героя

В стилях живут одновременно `.hero` (строки 139–148, зелёный блок с
иллюстрацией) и `.start-panel` (строки 466–487, градиентная панель).
Оформлены по-разному: разные радиусы (21px против 24px), разные отступы
(30/32px против 34px), разные фоны, разная типографика заголовка. Это следы
двух дизайнерских подходов, оставленных в репозитории вместе.

### 1.5 Плотность одинакова везде

Всё — белая скруглённая карточка на светло-зелёном. Одинаково выглядят:

- **решение** («выбрать эту программу целью») — требует внимания;
- **справка** («условия приёма») — читается один раз;
- **статус** («ближайший шаг») — проверяется каждый день;
- **предупреждение** («источники расходятся») — определяет доверие.

Визуальный вес у всех четырёх одинаковый. Глазу негде зацепиться, и каждый
экран читается как сплошное полотно. Это главная причина ощущения
«безликости» — не цвет и не шрифт, а **отсутствие иерархии поверхностей**.

### 1.6 Эргономические провалы по потокам

#### Анкета: один шаг из пяти содержит 79% всех вопросов

Измерено:

| Шаг | Полей всего | Видно при пустых ответах |
| --- | --- | --- |
| `education` | 4 | 3 |
| `status` | 3 | 2 |
| `direction` | 4 | 3 |
| **`exams`** | **54** | 7 |
| `resources` | 3 | 2 |
| **Итого** | **68** | |

Шаг «Экзамены» — это шесть экзаменов по девять полей: состояние, дата
записи, дата сдачи, ожидаемая дата результата, дата публикации, общий балл,
компоненты, срок действия. Вкладки шагов при этом рисуются **одинаковыми
плитками**: «шаг 4 из 6» ничем не намекает, что четвёртый шаг в восемнадцать
раз больше первого. Человек входит в него, рассчитывая на минуту, и
проваливается в анкету на двадцать полей.

Условная видимость спасает лишь отчасти: как только отмечено «сдавал IELTS»,
разворачивается девять полей подряд без визуальной группировки.

#### Выход из демо-режима меньше пальца

`.demo-pill` — это `<button>`, единственный способ выйти из демонстрационного
профиля:

```
.demo-pill { font-size: 11px; padding: 5px 10px; }          /* ≈25px высотой */
@media (max-width: 760px) { .demo-pill { font-size: 9px; padding: 4px 7px; } }  /* ≈21px */
```

В том же файле объявлено `--tap: 44px`. На мобильном контрол вдвое меньше
собственного норматива — и это не второстепенная ссылка, а аварийный выход.

Хуже: на мобильном `.workspace-bar--overview { display: none }` (строка 607)
прячет всю панель на главной. Признак «вы в демо-режиме» **исчезает вместе с
кнопкой выхода** ровно на том экране, куда демо приводит.

#### Прогресс-степпер на мобильном теряет контекст

`.journey li:not([data-current='true']) { display: none }` (строка 614) на
узком экране оставляет только текущий шаг. Смысл степпера — показать, где ты
в пути; свернув его до одного пункта, мы оставили декорацию.

#### Двухшаговое сохранение результата не объясняет себя

Кнопка «Подтвердить и сохранить» отключена, пока не нажата «Показать
последствия». Механика правильная — она не даёт записать балл, не увидев,
что изменится. Но **отключённая кнопка ничего не объясняет**: причина
появляется только текстом рядом, и то не всегда. Человек видит неактивный
элемент и не понимает, чего от него хотят.

### 1.7 Техническая подоплёка макета

- Боковая панель фиксированной ширины с компенсацией `margin-left: 236px`,
  повторённой как `210px` и `0` в двух медиазапросах. Три числа, которые
  обязаны совпадать, живут в шести местах.
- Анимации появления расставлены по `nth-child(2)`, `nth-child(3)`,
  `nth-child(n+4)` — привязаны к порядку разметки и ломаются при любой
  перестановке блоков.
- `color-scheme: light` — тёмной темы нет вообще.
- `.question-card input { min-height: 50px !important; font-size: 16px !important; }` —
  правильное решение (16px предотвращает зум на iOS), реализованное через
  `!important` из-за конфликта слоёв.

## 2. Целевая система

### 2.1 Принцип, из которого следует всё остальное

> **Уверенность вещи должна быть видна раньше, чем её содержание.**

Пользователь должен различать «это проверено», «это с ваших слов», «это мы
не знаем» и «источники спорят» **до того, как прочитает текст**. Сейчас все
четыре состояния — одинаковые карточки с разноцветным бейджем где-то сбоку.

Практически это означает четыре уровня поверхности, а не один:

| Уровень | Назначение | Приём |
| --- | --- | --- |
| **Решение** | То, что человек делает сейчас | Максимальный контраст, плотная типографика, единственная главная кнопка в зоне видимости |
| **Факт** | Подтверждённые данные каталога | Спокойная поверхность, крупные числа, источник рядом |
| **Оценка** | Наш расчёт по правилам | Отличается фоном и явной подписью «по вашим ответам» |
| **Неизвестность** | Пробел или спор источников | **Собственная визуальная форма** — не бейдж, а штриховка/незакрытая рамка, читаемая периферийным зрением |

Последняя строка — ключевая и она же самая нетривиальная. Предлагаемый приём:
неопределённые значения получают **незамкнутую левую границу и лёгкую
диагональную штриховку фона**, одинаковые на всех экранах. Это даёт то, чего
не даёт бейдж: неопределённость становится узнаваемой по форме, а не по
чтению подписи, и её нельзя случайно пропустить при беглом просмотре.

### 2.2 Токены: одна шкала, ноль литералов

**Отступы** — модульная шкала с шагом 4px, семь ступеней, и правило: в
компонентах не встречается ни одного `px` в `padding`/`margin`/`gap`.

```
--space-1: 4px    --space-2: 8px    --space-3: 12px   --space-4: 16px
--space-5: 24px   --space-6: 32px   --space-7: 48px   --space-8: 64px
```

**Типографика** — шкала на 7 ступеней вместо 22 размеров, в `rem`, с
привязанным межстрочным интервалом. Ни одного значения ниже 13px.

| Роль | Размер | Интерлиньяж | Где |
| --- | --- | --- | --- |
| `display` | `clamp(2rem, 1.4rem + 1.5vw, 2.75rem)` | 1.1 | H1 страницы |
| `title` | 1.5rem | 1.25 | Заголовок карточки-решения |
| `heading` | 1.25rem | 1.3 | H2 секции |
| `subhead` | 1.0625rem | 1.4 | H3, заголовок задачи |
| `body` | 1rem | 1.6 | Основной текст |
| `support` | 0.875rem | 1.55 | Пояснения, мета |
| `label` | 0.8125rem | 1.4 | Подписи полей, eyebrow |

**Цвет** — палитра сокращается со 142 хексов до примерно 24 токенов и
описывается в HSL с расчётными оттенками. Обязательное условие: каждая пара
«текст на фоне» проверяется на контраст ≥ 4.5:1, состояния (met / not-met /
unknown / conflict) различимы **не только цветом** — у каждого есть глиф и
форма.

**Радиусы** — три ступени вместо двенадцати: `6px` (контролы), `12px`
(карточки), `20px` (крупные панели).

### 2.3 Один слой стилей, слоистая каскадность

Файл переписывается целиком с `@layer`:

```
@layer reset, tokens, base, layout, components, utilities;
```

Это убирает саму возможность второго слоя-надстройки: переопределения
становятся структурными, а не «допишем в конец». Цель — **ноль `!important`**
и **ноль селекторов, объявленных дважды**.

### 2.4 Макет на сетке, а не на отступах

Оболочка переходит с `position: fixed` + `margin-left` на CSS Grid:

```
.shell { display: grid; grid-template-columns: var(--rail) 1fr; }
```

Ширина панели становится одним токеном, меняющимся в медиазапросе. Три
числа в шести местах превращаются в одно.

Брейкпоинтов остаётся **три** вместо восьми: `600px` (телефон → планшет),
`960px` (планшет → компактный десктоп), `1280px` (полный десктоп). Всё
остальное решается `clamp()` и автоматическими сетками.

### 2.5 Тёмная тема

Добавляется как равноправная: `color-scheme: light dark`, токены
переопределяются в `@media (prefers-color-scheme: dark)`. Для продукта, в
котором люди сидят вечерами перед экзаменами, это не украшение.

### 2.6 Движение

Текущие задержки по `nth-child` заменяются на **одну** анимацию появления
контента страницы без каскада. Каскадная «лесенка» блоков добавляет до 90 мс
воспринимаемой задержки и ломается при перестановке. Сохраняется и
усиливается другое: обратная связь на действие (кнопка, переход статуса
задачи) — именно там движение полезно.

## 4. Проверка удобства

Переработка интерфейса без проверки — это замена одних догадок другими.
Ниже — что именно и чем проверяется. Часть инфраструктуры уже есть:
в проекте настроен Playwright (`playwright.config.ts`, каталог `e2e/`),
прогон детерминирован фиксированными часами и отдельным каталогом данных.

### 4.1 Сначала — снять базовую линию

До первой строки нового CSS зафиксировать текущее состояние, иначе
«стало лучше» будет непроверяемым:

1. **Скриншоты всех девяти экранов** в трёх ширинах (360, 768, 1440) —
   через Playwright, в репозиторий не коммитить, хранить как артефакт.
2. **Замер длины потоков**: число кликов и полей от пустого профиля до
   построенного маршрута. Сейчас: анкета из 5 шагов и до 68 полей, затем
   выбор цели, затем маршрут.
3. **Инструментальные метрики**: Lighthouse (производительность,
   доступность, лучшие практики) на тех же девяти экранах.

### 4.2 Адаптивность

| Проверка | Как | Критерий |
| --- | --- | --- |
| Нет горизонтальной прокрутки | Playwright: `scrollWidth <= clientWidth` на всех экранах | 360, 390, 768, 1024, 1440, 1920 |
| Текст не обрезается | Скриншотное сравнение | Нет `overflow: hidden` с потерей содержимого |
| Таблица сравнения на телефоне | Ручная проверка + скриншот | Читается без зума |
| Ориентация | 360×640 и 640×360 | Обе работоспособны |

### 4.3 Размеры целей нажатия

Автоматическая проверка: обойти все интерактивные элементы
(`a`, `button`, `input`, `select`, `summary`, `[role=button]`) на каждом
экране и убедиться, что прямоугольник каждого **не меньше 44×44 CSS-пикселей**
и что соседние цели разнесены минимум на 8px.

Это ловит ровно тот класс дефектов, которым сейчас страдает `.demo-pill`.
Проверка обязана падать, а не предупреждать.

### 4.4 Доступность

| Что | Чем | Критерий |
| --- | --- | --- |
| Автоматические нарушения | `@axe-core/playwright` на всех экранах | Ноль нарушений уровня serious и critical |
| Контраст | Тот же прогон + ручная проверка состояний | ≥ 4.5:1 для текста, ≥ 3:1 для границ контролов |
| Клавиатура | Playwright: пройти анкету целиком без мыши | Все поля достижимы, порядок обхода совпадает с визуальным |
| Видимость фокуса | Скриншот каждого сфокусированного контрола | Обводка видна на любом фоне |
| Скринридер | Ручная проверка NVDA на трёх ключевых потоках | Заголовки образуют осмысленное оглавление; `aria-label` на `div` из §1.3 устранены |
| Не только цвет | Ручная проверка в градациях серого | Статусы условий различимы |
| Уменьшенное движение | `prefers-reduced-motion: reduce` | Анимаций нет, функциональность цела |

### 4.5 Трение в потоках

Пять потоков, по каждому — измеримая цель:

| Поток | Метрика сейчас | Цель |
| --- | --- | --- |
| Пустой профиль → первая рекомендация | 5 шагов, до 68 полей | ≤ 12 обязательных полей до первого результата; остальное — уточнение после |
| Рекомендации → цель выбрана | 3 перехода | 2 перехода, выбор цели доступен прямо из карточки списка |
| Отметить выполненное действие | 1 клик + ожидание | То же, но со мгновенной оптимистичной отрисовкой |
| Внести результат экзамена | 2 шага, причина блокировки неочевидна | 2 шага, каждый подписан, кнопка объясняет своё состояние |
| Сравнить два варианта | Список → отметить → кнопка | Отметка прямо в списке программ, сравнение доступно оттуда же |

Отдельно — **проверка на пяти живых людях** (целевая аудитория: 11 класс и
их родители), сценарий «подберите себе программу и скажите, что делать
дальше», без подсказок. Фиксируется: где остановились, что переспросили,
что поняли неправильно. Пять человек находят большинство проблем удобства;
это дешевле любой автоматики и ловит то, что она не видит.

### 4.6 Защита от регрессий

| Что | Чем |
| --- | --- |
| Визуальные регрессии | Скриншотное сравнение Playwright на девяти экранах × три ширины |
| Дисциплина стилей | Линтер CSS: запрет `!important`, запрет px-литералов в отступах, запрет hex вне блока токенов |
| Поведение | Существующие сквозные сценарии в `e2e/` — они проверяют поток, а не оформление, и обязаны пройти без правок |
| Доступность | `@axe-core/playwright` в том же прогоне |

Последняя строка важна: **переработка интерфейса не должна потребовать
переписывания сквозных тестов**. Они опираются на роли, доступные имена и
атрибуты форм, а не на классы. Если тест сломался — значит, сломалась
семантика, и это повод остановиться, а не поправить селектор.

## 6. Чего делать не нужно

Список важен не меньше остального — он защищает то, что в продукте уже
сделано правильно:

- **Не вводить UI-кит.** Отсутствие внешних библиотек — осознанное решение
  проекта, и оно себя оправдывает: вся разметка семантична, а сквозные тесты
  строятся на ролях и ARIA. Готовый кит это сломает.
- **Не сводить поступление к одной цифре.** Ни процента готовности, ни
  «шанса поступления». Это прямо запрещено логикой продукта, и счётчики
  намеренно показывают раздельные числа.
- **Не прятать неопределённость ради красоты.** Прочерк вместо «источник не
  опубликовал» сделает интерфейс чище и продукт бесполезнее.
- **Не трогать разметку форм без причины.** Атрибуты `name`, связки
  `aria-describedby`, `role="alert"` и `role="status"` — то, на чём держится
  и доступность, и сквозные тесты.
- **Не менять тексты интерфейса заодно с оформлением.** Формулировки
  подобраны под честность продукта; их правка — отдельная задача с отдельной
  проверкой.

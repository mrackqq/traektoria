# Система «сигнал и неизвестность»

Визуальный язык «Траектории». Один файл, из которого можно восстановить
оформление, не глядя на макеты. Эскизы лежат в Claude Design, код системы
целиком в `src/app/globals.css`.

---

## Идея

Продукт отличает «не выполнено» от «неизвестно» и не выдумывает срок,
которого нет в источнике. Это его единственное настоящее отличие от
агрегатора, и до переработки оно было набрано серым по серому в подвале.

Система строится вокруг этого различия. **У неизвестности своя форма**:
рамка не замкнута справа, поле заштриховано. Её видно боковым зрением, не
читая.

---

## Цвет

Шкала построена в OKLCH равными шагами по светлоте, поэтому слои не
слипаются и ни один не проваливается. Токены в `:root`.

| Токен | Значение | Роль |
| --- | --- | --- |
| `--c-bg` | `#14161C` | основа страницы |
| `--c-surface` | `#1B1E26` | карточка |
| `--c-surface-sunken` | `#232732` | вложенный блок, поле ввода |
| `--c-border` | `#2F3440` | граница |
| `--c-border-strong` | `#414756` | активная граница, штриховка |
| `--c-text` | `#F3F4F8` | основной текст |
| `--c-text-muted` | `#A9AEBD` | пояснения |
| `--c-text-dim` | `#7E8496` | подписи, надзаголовки |
| `--c-accent` | `#C6F24B` | сигнал |
| `--c-on-accent` | `#14161C` | текст **на** акценте |
| `--c-warn` | `#F4C46B` | требует внимания |
| `--c-risk` | `#F2806E` | не проходит |

**Акцент ровно один на весь продукт** и означает ровно одно: «вот что
делать сейчас». По площади около десяти процентов, на экране появляется
один раз. Поэтому его нельзя перепутать.

**Текст на акценте только `--c-on-accent`.** Белый по лайму нечитаем: это
самая частая ошибка при переносе светлой кнопки в тёмную тему.

Проверено: текст от 5.2:1, акцент на основе 14:1, тёмный на акценте 14:1.

### Чего в палитре нет намеренно

Тёплой бумаги (`#f5f2ea` и родственные), латуни, эспрессо. Это набор,
которым закрывают любой «премиальный» бриф, и продукт в нём теряет лицо.
Фиолетово-синего свечения тоже нет.

---

## Шрифт

Подключены через `next/font` в `src/app/layout.tsx`, с кириллическим
набором. Ссылки на Google Fonts в разметке нет.

| Шрифт | Где | Почему |
| --- | --- | --- |
| **Unbounded** 600–800 | `h1`, `h2`, крупные числа | дисплейный гротеск, кириллица в основе рисунка |
| **Onest** 400–700 | интерфейс и текст | не Inter и не Roboto, кириллица родная |
| **JetBrains Mono** 400–500 | даты, баллы, суммы | цифры встают в столбец и сравниваются за один проход |

Антиквы нет. «Творческий бриф значит засечки» — самый вычисляемый признак
машинного дизайна. Гротеск не скучный, он дефолтный по той же причине, по
которой чёрный дефолтный в одежде.

**Дисплейный шрифт шире обычного**, поэтому в узких колонках короткий
заголовок в нём рвётся на две строки. Там заголовок возвращается к
`--font-body`: список исключений в `globals.css`.

## Четыре поверхности

| Поверхность | Как выглядит | Что означает |
| --- | --- | --- |
| **Решение** | заливка акцентом, тёмный текст | одно действие на экран |
| **Факт** | `--c-surface`, замкнутая рамка | есть источник и дата проверки |
| **Вывод** | `--c-surface-sunken`, кромка акцентом слева | посчитал сервис, а не напечатано в приказе |
| **Неизвестность** | штриховка, рамка разомкнута справа | источник не дал данных |

Штриховка вынесена в токен `--hatch` и применяется к `.badge--unknown`,
`.compare__value--unknown`, `.task--blocked`,
`.requirement-node[data-status='UNKNOWN']`.

## Движение

Кривые сильнее встроенных: у стандартных нет нужной резкости.

```css
--ease-out: cubic-bezier(.23, 1, .32, 1);
--ease-in-out: cubic-bezier(.77, 0, .175, 1);
```

**`ease-in` не используется никогда.** Он откладывает начало ровно в тот
момент, когда человек смотрит внимательнее всего, и интерфейс кажется
вязким при той же длительности.

| Что | Длительность | Зачем |
| --- | --- | --- |
| нажатие кнопки, `scale(.97)` | 160 мс | интерфейс услышал |
| ховер, смена цвета | 160–180 мс | наводка понятна |
| раскрытие подробностей | 200 мс | смена состояния |
| появление блока страницы | 300–340 мс, каскад 30–120 мс | порядок чтения |
| подтверждение и ошибка | 220 мс от `scale(.97)` | пришло после действия |

Правила, которые соблюдаются:

- Анимируются только `transform` и `opacity`: они идут мимо раскладки и
  отрисовки.
- Ничего не появляется из `scale(0)`: в реальном мире ничто не возникает
  из ничего.
- Ховер закрыт в `@media (hover: hover) and (pointer: fine)`: на тач-экране
  он срабатывает от касания и залипает.
- Всё, что человек видит десятки раз за сессию, движением не украшается.
  Анимация без ответа на вопрос «что она сообщает» не добавляется.
- `prefers-reduced-motion: reduce` убирает перемещение, но оставляет цвет и
  прозрачность: сокращённое движение это меньше движения, а не его
  отсутствие.

## Формы

Одно правило на весь продукт, смешанных систем нет.

- карточка `--r-lg` 20px
- элемент управления 10–11px
- метка-пилюля 999px
- цель нажатия не меньше `--tap` 44px

## Что проверять после правок

```bash
npm run verify      # 545 юнит-тестов и пороги покрытия
npm run test:e2e    # 46 сквозных, включая эргономику
npm run shots       # снимки в design-shots/ для глазной проверки
```

Сквозные тесты эргономики стерегут цели нажатия 44px, видимый фокус,
отсутствие горизонтальной прокрутки на 360/390/768 и проходимость анкеты с
клавиатуры. **Если после правки оформления упал сквозной тест, сломалась
семантика, и это повод остановиться, а не поправить селектор.**

## Что осталось за рамками этого этапа

Перенесён визуальный язык: цвет, шрифт, поверхности, движение. Работа с
плотностью из эскизов требует переделки компонентов и не сделана:

- «Мой план» сворачивается до строки на действие с раскрытием по нажатию
- «Программы» получают фильтры, сортировку и свёрнутые группы
- Анкета сначала спрашивает, какие экзамены вас касаются
- Телефон отдаёт первый экран действию, навигация уходит вниз

Ожидаемый эффект по измерениям из `DESIGN_REVIEW.md`: `/route` с 4614 px до
1500, `/programs` с 7502 px до 3000, первое действие на телефоне выше 250 px.

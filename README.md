# ТРАЕКТОРИЯ

**Персональный маршрут поступления.** Сервис превращает профиль абитуриента
в понятный план: куда поступать, почему подходит именно этот вариант и что
сделать сегодня.

Решение для LOCUS Startup Hackathon 2026, кейс 02 «Персональный маршрут поступления».
Код сабмита: `LOCUSCASE2`.

> Next.js 15 · TypeScript strict · Zod · OpenRouter (`google/gemini-2.5-flash`)
> 144 автотеста · typecheck и production-сборка проходят

## Коротко

| | |
| --- | --- |
| **Для кого** | Ученик 10–11 класса и выпускник школы из Казахстана, бакалавриат |
| **Что решает** | Вместо списка вузов — маршрут: подбор с объяснением, план и ближайший шаг |
| **Университеты** | Настоящие, со ссылками на приёмные комиссии |
| **Условия и цены** | Ориентировочные, помечены «проверьте у вуза» |
| **Роль AI** | Объясняет расчёт, не принимает решений и не считает шансы |
| **Данные** | Анонимная сессия в cookie, без аккаунтов и без документов |

**Запуск за три команды**

```bash
npm install
npm run dev      # http://localhost:3000
```

Ключ OpenRouter не обязателен: без него продукт работает полностью, объяснения
показываются по правилам сервиса.

## Задача и аудитория

Поступление состоит из десятков решений: направление, страна, университет, экзамены,
документы, сроки. Информация разрознена, рекомендации общие, и абитуриент не понимает,
что подходит именно ему и какое действие выполнить сейчас.

**Аудитория:** ученик 10–11 класса или выпускник школы из Казахстана, поступающий
на бакалавриат — в Казахстане или за рубежом.

## Что делает продукт

Один связный путь: **вход → анкета → диагностика → рекомендации → сравнение →
выбор цели → маршрут → ближайшее действие и прогресс.**

- **Анкета** — образование, средний балл, профильные предметы, гражданство и категория,
  направления, страны, языки, экзамены, время и бюджет. У каждого вопроса есть явное
  «не знаю»: оно не равно пустому ответу и ведёт к неопределённому выводу, а не к догадке.
- **Диагностика** — образовательная цель, сильные стороны, ограничения, пробелы
  и приоритет подготовки.
- **Рекомендации** — программы разбиты на «подходят вам», «альтернативы за пределами
  ваших фильтров», «требуют проверки» и «сейчас не подходят». У каждой карточки —
  причины и, для исключённых, причина исключения.
- **Сравнение** — пути подачи сопоставляются по условиям, деньгам, срокам и языку.
  Неизвестное значение показывается словами, а не прочерком.
- **Маршрут** — обратное планирование от каждой внешней отсечки: экзамены, документы,
  зависимости, резерв времени, недельная нагрузка.
- **Ближайшее действие** — один выделенный шаг с объяснением, почему выбран именно он,
  и сохранением прогресса.
- **Сценарии** — «что будет, если» бюджет сократится или результат задержится. Расчёт
  идёт на копии данных и ничего не меняет.

## Чего продукт не делает

Это принципиальная часть решения, а не оговорка:

- не называет вероятность или процент шансов на поступление;
- не гарантирует зачисление;
- не придумывает университеты, требования, стоимость и сроки — всё берётся из каталога;
- не подаёт заявления за пользователя;
- не подставляет неподходящие программы, чтобы получилось «не менее трёх».

## Архитектура

```
src/core/     чистое доменное ядро: без сети, без файлов, без React
  kernel/       состояния условий, даты, деньги, шкалы, воспроизводимость
  catalog/      синтетический каталог: вузы, программы, кампании, пути подачи
  profile/      анкета, валидация, диагностика, «что изменилось»
  eligibility/  вычисление дерева требований и подбор программ
  planning/     мост к цели: граф действий, обратное планирование, ограничения профиля
  progress/     статусы действий, команды, счётчики, ближайший шаг
  scenarios/    стресс-тест маршрута и diff «было → станет»
src/server/   прикладной слой: хранилище, сессии, часы, AI
  ai/           OpenRouter: конфиг, транспорт, контекст, схема, кеш, фильтры
src/app/      интерфейс: страницы, серверные действия, компоненты
```

Правила границы:

- ядро не знает про HTTP, файлы и модель — его функции чистые и принимают часы параметром;
- решения принимает ядро, AI только объясняет;
- сеть живёт только в `src/server/ai`.

## Запуск

```bash
npm install
npm run dev                    # http://localhost:3000
npm run dev -- --port 3005     # другой порт
```

Продуктовая сборка и запуск:

```bash
npm run build                  # собирает в .next-build
npm start                      # запускает ту же .next-build
npm start -- --port 3012       # production на другом порту
```

`build` и `start` берут папку сборки из одного места (`scripts/next-run.mjs`),
поэтому «Could not find a production build» из-за расхождения путей больше не
возникает. Dev при этом остаётся на `.next`, так что продуктовая сборка не
конфликтует с работающим dev-сервером — их можно держать одновременно.

Папку сборки можно задать явно:

```bash
NEXT_DIST_DIR=.next-prod npm run build
NEXT_DIST_DIR=.next-prod npm start -- --port 3012
```

Проверки:

```bash
npm run typecheck
npm test
```

### Переменные окружения

Создайте `.env.local` в корне (он исключён из Git):

```
OPENROUTER_API_KEY=ваш_ключ
OPENROUTER_MODEL=google/gemini-2.5-flash
```

| Переменная | Обязательна | Назначение |
| --- | --- | --- |
| `OPENROUTER_API_KEY` | нет | Ключ OpenRouter. Без него продукт работает полностью, но объяснения показываются по правилам сервиса. |
| `OPENROUTER_MODEL` | нет | Модель. По умолчанию `google/gemini-2.5-flash`. |
| `OPENROUTER_TIMEOUT_MS` | нет | Таймаут запроса, по умолчанию 25000. |
| `TRAJECTORY_DATA_DIR` | нет | Каталог состояния, по умолчанию `.data`. |
| `TRAJECTORY_CLOCK` | нет | Фиксированный момент расчёта для воспроизводимого демо и тестов. |

Ключ читается **только** на сервере, через `process.env.OPENROUTER_API_KEY`.
Префикс `NEXT_PUBLIC_` не используется нигде: всё помеченное им попало бы в браузер.

## Роль AI

AI отвечает за **объяснение**, а не за решение. Подбор, планировщик и вердикты
детерминированы и работают без модели.

Модель получает уже посчитанный снимок и возвращает строгий JSON:

- резюме профиля, сильные стороны и ограничения;
- «почему подходит» и «чем придётся заплатить» по каждой программе;
- компромиссы между вариантами при сравнении — именно между теми, что отмечены
  галочками, включая варианты вне общего топа;
- инструкции к действиям маршрута;
- разбор ближайшего шага.

**Что гарантирует честность:**

1. **Схема.** JSON Schema уходит в запрос, поддержка структурированного вывода
   проверяется у OpenRouter, ответ валидируется Zod. Числовых полей в схеме нет —
   но это не защита сама по себе: цифры прекрасно живут внутри строк, поэтому
   строки проверяются отдельно.
2. **Идентификаторы.** `pathId` и `taskId` из ответа сверяются со списком текущего
   расчёта. Ссылка на несуществующую программу отбрасывается.
3. **Запрещённые утверждения.** Вероятности, гарантии и обещания зачисления —
   включая числительные словами («девяносто процентов») и косвенные формулировки.
4. **Привязка к фактам — по субъекту и показателю.** Каждый факт расчёта имеет
   тройку «субъект (программа, задача или профиль) + показатель + значение».
   Модель ссылается на факт идентификатором, а значение подставляет сервер.
   Свободный текст проверяется в области своего субъекта:
   - дата сверяется целиком, а не по году: «до 12 октября 2027 года» отбрасывается,
     если отсечка программы — 5 июля 2027;
   - средний балл не может стать порогом IELTS, а стоимость одной программы —
     стоимостью другой;
   - если предложение говорит о балле, сумме, сроке или требовании, послабление
     для мелких чисел не действует: «достаточно IELTS 5» требует подтверждения;
   - утверждение «обучение бесплатное» требует факта нулевой стоимости.
5. **Источник фактов — каталог.** Баллы, стоимость, сроки и источники рисует
   интерфейс из расчёта, а не текст модели. Служебные идентификаторы заменяются
   человеческими названиями.
6. **Откат.** Нет ключа, таймаут, ошибка сети или неверный JSON — показываются
   объяснения по правилам с явной пометкой режима и причины. Диагностика профиля
   считается правилами и доступна без модели вообще.

**Чего эти проверки НЕ делают.** Это не верификация смысла. Проверяется только то,
что утверждение ссылается на факт нужного субъекта и показателя и не содержит
запрещённых обещаний. Модель может написать правдоподобную неверную фразу без
единого числа, и такая фраза пройдёт. Поэтому:

- текст модели нигде не называется проверенным — рядом с ним прямо сказано, что
  смысловая верность не гарантируется;
- числовые условия, сроки и стоимость показываются отдельной строкой фактов,
  подставленной сервером из расчёта;
- при расхождении текста и расчёта верен расчёт;
- словарь показателей покрывает только те величины, которые мы умеем подтверждать
  (баллы, пороги, стоимость, бюджет, финансирование, сроки, нагрузка,
  длительность). Утверждение о величине вне этого списка проверяется слабее.

Версии промпта и политики проверки (`PROMPT_VERSION`, `GUARDRAILS_VERSION`) входят
в ключ кеша: изменение правил обесценивает прежние ответы.

**Экономия запросов.** Ответ кешируется по ключу, в который входят посетитель,
ревизия профиля, отпечаток расчёта, версия каталога, выбранная цель, прогресс,
состав маршрута, выбранная для сравнения пара, модель и версия промпта.

Ключ обязан быть стабильным при неизменных ответах. Для этого каталог версионируется
по **периоду обновления**, а не по моменту чтения: `verifiedAt` источников и версия
каталога считаются от начала суток, поэтому `catalogScopeHash` и `inputHash` не
меняются между двумя соседними запросами. Часы приложения при этом настоящие —
квантуется публикация каталога, а не время расчёта. Проверено на живом сервере:
первый запрос страницы — 11,7 с (обращение к модели), следующий и переход на другую
страницу — 0,27 с и 0,16 с из кеша.

Ответ перестаёт использоваться, когда истекает срок кеша (30 минут), меняется профиль,
каталог, цель, прогресс или выбранная пара. Параллельные запросы с одним ключом
объединяются в один.

**Что уходит в модель.** Только то, что нужно для объяснения: ответы анкеты,
выводы правил и подписи каталога. Идентификатор владельца, ревизии, хэши и журнал
операций не передаются. Имени, почты, даты рождения и документов в продукте нет
вообще — их негде ввести.

## Сценарий проверки

1. Открыть `/` в новом браузере. Видно стартовый экран: кому сервис помогает,
   что даст, кнопки **«Создать мой маршрут»** и **«Посмотреть демо»**. Персональной
   цели и маршрута нет — ответов ещё не было.
2. **Посмотреть демо** — отдельное пространство данных: синтетический профиль
   ученика 11 класса (сдал ЕНТ и ждёт результат, бюджет 3 млн ₸, интересы
   «информатика» и «инженерия», страны KZ и TR). В шапке — «Демонстрационный
   профиль» и кнопка выхода к своему профилю.
3. `/profile` — диагностика по правилам: цель, сильные стороны, ограничения,
   приоритет подготовки. Она видна и без ключа OpenRouter.
4. `/programs` — шесть вариантов «подходят вам», четыре альтернативы за пределами
   фильтров, три требуют проверки, восемь исключены с причинами. Пояснения модели —
   свёрнутым блоком под подбором, а не перед ним.
5. `/compare` — отметить два варианта: сравнение и разбор компромиссов именно по ним.
6. Открыть программу → **«Сделать эту программу своей целью»** → `/route`:
   маршрут именно к ней. Выбор сохраняется и не переключается при изменении рейтинга.
7. `/route` — отметить действие, обновить страницу: прогресс на месте. Рекомендуемые
   активности помечены «Рекомендуем, не требование приёма».
8. `/profile/edit` — изменить бюджет, страну, интерес или экзамен и применить анкету.
   На обзоре появится блок «Что изменилось» для текущей ревизии профиля.
9. Поставить год поступления, на который кампаний нет (например, 2029): маршрут
   к прошлогоднему набору НЕ строится, показывается причина и доступные годы.

Реакция на изменения проверена на демо-профиле:

| Изменение | Результат |
| --- | --- |
| Бюджет 3 млн → 1,2 млн | подходят 6 → 2, меняется первый вариант |
| Только Турция | первым становится турецкая программа, 9 вариантов уходят в альтернативы |
| Интерес «бизнес и экономика» | первым становится Business Administration |
| Категория «иностранный заявитель» | пути «только для граждан РК» уходят в исключённые |
| Год поступления 2029 | подходящих нет, названа причина и годы, на которые есть данные |
| ЕНТ уже сдан | из плана исчезают подготовка, регистрация и сдача |

## Данные и источники

**Университеты и программы — настоящие.** Восемь вузов (Nazarbayev University,
КБТУ, Astana IT University, SDU University, Satbayev University, МУИТ,
Technical University of Munich, Middle East Technical University), четырнадцать
программ, две кампании приёма, пути подачи с разными условиями.

**Пороговые баллы, стоимость и сроки — ориентировочные.** Они нужны, чтобы
механика подбора и планирования работала на правдоподобных величинах, но
официальными значениями не являются. Каждый источник помечен как требующий
подтверждения и ведёт на реальную страницу приёма соответствующего вуза —
пользователь видит и пометку, и адрес, по которому значение можно проверить.
Кейс прямо допускает такой вариант: «фактические требования и дедлайны
сопровождаются источниками либо пометкой о демонстрационных данных».

В каталог заложены ситуации, которые обычно прячут: устаревший источник,
расхождение двух источников по одному сроку, срок без указанного времени и часового
пояса. Продукт показывает их как неопределённость, а не как факт.

Реальных условий приёма, сумм и дедлайнов в продукте нет. Перед подачей документов
всё нужно проверять у приёмной комиссии.

## Готовые компоненты

- `next`, `react`, `react-dom` — фреймворк и рантайм;
- `zod` — проверка ответа модели;
- `typescript`, `@types/*` — типы и проверка.

UI-китов, библиотек компонентов, CSS-фреймворков и генераторов графики не
используется. Вёрстка, дизайн-система, иконки и вся доменная логика написаны в проекте.

## Ограничения

- Пороговые баллы, стоимость и сроки в каталоге ориентировочные: перед подачей
  документов их нужно подтвердить на сайте вуза. Продукт показывает работу
  механики на настоящих университетах, а не официальные условия приёма.
- Хранилище файловое и рассчитано на один процесс. Для нескольких инстансов нужна
  другая реализация `Store`; контракт для этого уже выделен.
- Сессия анонимная, на cookie. Это разделяет данные посетителей, но не заменяет
  учётную запись: очистка cookie означает потерю доступа к своему профилю.
- Кеш объяснений живёт в памяти процесса и очищается при перезапуске.
- Версия каталога обновляется раз в сутки: правка состава данных требует ручного
  изменения `CATALOG_DATA_VERSION`, иначе новый набор подхватится только в следующем
  периоде.
- Модель объясняет, но не проверяет факты: её текст всегда вторичен по отношению
  к расчёту, и при расхождении верен расчёт.
- Проверка достоверности отбрасывает подозрительные фрагменты консервативно.
  Полезный текст с числом, которого не было во входных данных, будет убран —
  это осознанный размен в пользу честности.
- Рекомендуемые активности (портфолио, конкурсы) — подсказка продукта, а не
  требование вуза. Они не закрывают условий приёма, не блокируют подачу заявления
  и не учитываются в проверке недельной нагрузки.
